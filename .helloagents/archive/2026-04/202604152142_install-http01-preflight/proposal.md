## 1. 需求

### 背景
当前安装脚本支持 `--cert-domain` 和 `--cert-http-port`，但用户在 HTTP-01 部署失败时，容易把 `http_port` 理解成“让 CA 改用其他公网端口验证”。
仓库现有实现里，`internal/cert/cert.go` 将 `cert.http_port` 传给 certmagic 的 `AltHTTPPort`，本质是本地监听端口，不会改变 ACME HTTP-01 仍需从公网访问 `80` 端口这一约束。
这会导致 80 端口不可达场景下，用户继续尝试改端口，最后只得到模糊的失败日志。

### 目标
- 明确 HTTP-01 的真实限制：公网仍需可访问 `80` 端口。
- 当用户设置 `--cert-http-port` 时，明确说明这是本地监听端口，若不等于 `80` 则必须已有 `80 -> 自定义端口` 转发。
- 在安装脚本部署后增加轻量预检与排障提示，尽早暴露“域名未解析到本机 / 本地监听未建立 / 80 转发缺失”这类问题。
- 保持现有 HTTP-01 和 DNS-01 功能不变，不引入新的证书模式。

### 约束条件
```yaml
时间约束: 本次只做安装脚本、说明文档和必要测试的增量修补
性能约束: 预检逻辑不得阻塞正常安装太久，失败时以提示为主
兼容性约束: 不改变现有 --cert-domain / --cert-http-port / --cert-mode dns 的参数语义
业务约束: 不能误导用户认为 HTTP-01 可以直接改成任意公网端口验证
```

### 验收标准
- [ ] 安装脚本在 HTTP-01 场景下输出清晰提示：公网验证仍依赖 80，`--cert-http-port` 仅代表本地监听端口。
- [ ] 当 `--cert-http-port` 不为 `80` 时，部署结果和排障提示里能明确给出“需要 80 转发到该端口”的说明。
- [ ] 文档和示例配置与脚本行为保持一致，不再把 `http_port` 描述成可替代公网 80 的能力。
- [ ] 相关脚本/配置校验测试通过。

## 2. 方案

### 技术方案
本次采用“说明清楚 + 本地预检 + 失败提示增强”的修补方案，而不改动 ACME 协议层行为。

具体实现：
- 在 `install.sh` 中新增 HTTP-01 预检辅助逻辑：
  - 统一生成 HTTP-01 约束提示文案。
  - 当 `cert_mode=http` 且设置了 `CERT_DOMAIN` 时，在部署结果中输出域名、公网 80 约束以及自定义监听端口对应关系。
  - 当 `CERT_HTTP_PORT != 80` 时，显式提示“必须保证公网 80 已转发到本机 ${CERT_HTTP_PORT}”。
  - 补充本地监听/域名解析相关诊断输出，帮助快速判断失败方向。
- 在 `README.md` 与 `config.yml.example` 中统一修改 `http_port` 说明，避免用户把它误认为任意公网验证端口。
- 视需要补充配置/脚本测试，保证文案与行为不回退。

### 影响范围
```yaml
涉及模块:
  - install: 安装脚本的 HTTP-01 结果输出、预检提示与帮助文本
  - docs: README 与示例配置的 ACME 说明同步
  - config: 如需测试，补充与 HTTP 端口语义相关的回归覆盖
预计变更文件: 3-4
```

### 风险评估
| 风险 | 等级 | 应对 |
|------|------|------|
| 提示文案过多影响安装输出可读性 | 低 | 只在 HTTP-01 相关场景输出增强提示 |
| 用户继续把自定义端口理解为公网验证端口 | 中 | 在参数说明、部署结果、排障提示三处重复强调 |
| 预检逻辑依赖系统命令差异 | 低 | 以保守检测和可选提示为主，不把预检失败当作硬阻断 |

## 4. 核心场景

> 执行完成后同步到对应模块文档

### 场景: HTTP-01 使用默认 80
**模块**: install / docs
**条件**: 用户仅传 `--cert-domain`
**行为**: 安装脚本按 HTTP-01 部署，并在结果中提示公网 80 必须可达
**结果**: 用户能正确理解失败原因优先检查域名解析与 80 端口

### 场景: HTTP-01 使用自定义本地监听端口
**模块**: install / docs
**条件**: 用户传入 `--cert-domain` 和 `--cert-http-port 8080`
**行为**: 安装脚本写入 `http_port: 8080`，同时明确说明这只是本地监听端口，公网仍需 `80 -> 8080` 转发
**结果**: 用户不会误以为 CA 会直接访问 8080

## 5. 技术决策

> 本方案涉及的技术决策，归档后成为决策的唯一完整记录

### install-http01-preflight#D001: 不新增伪“自定义公网端口 HTTP-01”，改为增强预检与提示
**日期**: 2026-04-15
**状态**: ✅采纳
**背景**: 用户希望在不引入 DNS-01 凭据的前提下，解决 80 端口受限时的证书申请体验问题。
**选项分析**:
| 选项 | 优点 | 缺点 |
|------|------|------|
| A: 声称支持任意公网端口 HTTP-01 | 表面上更符合用户直觉 | 与 ACME HTTP-01 真实约束不符，容易制造虚假能力 |
| B: 保持协议约束不变，增强预检与提示 | 行为真实、实现成本低、能直接减少误用 | 不能绕开 80 端口本身的限制 |
**决策**: 选择方案 B
**理由**: 当前仓库的 `http_port` 只是 certmagic 的本地监听端口。继续包装成“自定义公网验证端口”会让安装脚本和实际协议行为脱节。
**影响**: 影响 `install.sh`、`README.md`、`config.yml.example` 以及相关测试。
