# 技术设计: 中文文档与原生部署优化

## 技术方案
### 核心技术
- Markdown 文档重写
- Shell 参数解析扩展
- YAML 配置生成

### 实现要点
- 重写 `README.md` 为中文，并按“原生部署优先、Docker 其次”的顺序组织内容
- 将 `config.yml.example` 注释翻译为中文，突出 `runtime` 运行时内存调优项
- 在 `install.sh` 中增加 `--gomemlimit`、`--gogc` 参数，写入生成的节点配置

## 架构决策 ADR
### ADR-20260320-01: 文档默认推荐原生部署而非 Docker
**上下文:** 项目已有原生部署脚本，但 README 仅展示 Docker，导致用户误以为 Docker 是唯一入口。
**决策:** 将 README 的默认快速开始改为 `install.sh` 原生部署，并把 Docker 保留为可选方案。
**理由:** 该路径更贴近仓库现有能力，也更符合“减少 Docker 额外内存占用”的用户目标。
**替代方案:** 继续保留 Docker 作为唯一推荐入口 → 拒绝原因: 无法解决用户关于内存占用的直接诉求。
**影响:** 安装脚本帮助信息与配置示例必须同步更新，否则会造成文档与行为不一致。

## 安全与性能
- **安全:** 不在文档或脚本中写入真实令牌；新增参数仅写入本地配置文件
- **性能:** 原生部署减少容器层开销；通过 `gomemlimit` / `gogc` 提供细粒度内存控制

## 测试与部署
- **测试:** 执行 `go test ./...`，并用 `bash -n install.sh` 做脚本语法检查
- **部署:** 运维人员通过 `bash install.sh -a ... -t ... -n ... --gomemlimit 256MiB --gogc 50` 一键部署
